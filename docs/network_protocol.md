# 联机约定

当前联机标识为 **协议 29 / 构建 0.35.3**，定义于 `core/network_session.gd`。通信使用 ENet / UDP 7000，支持 2–4 人。所有玩家应运行相同构建；协议或构建标识不匹配时，客户端不能加入房间。

## 权威与通道

房主负责比赛阶段、玩家位置、口哨命中、泡泡爆裂和比分裁定。客户端发送输入请求，不上传可直接采用的位置或分数。房主更换或重连后，逻辑玩家 ID 保持稳定。

| 通道 | 传输 | 用途 |
| --- | --- | --- |
| 0 | 可靠 | 加入、外观、准备、加载确认、阶段变化、吹气按下/松开、口哨、最终成绩和房主正常交接 |
| 1 | 不可靠有序 | 房主状态快照 |
| 2 | 不可靠有序 | 移动输入帧；包含近期输入冗余 |
| 3 | 不可靠 | 时钟探测与回应 |
| 4 | 可靠 | 预备房主恢复检查点 |

移动使用 60 Hz 物理步长。客户端预测本机移动并根据房主确认重放未确认输入；其他玩家按房主时间戳插值。实际网络发送频率受房主帧率、延迟和丢包影响。

## 房间与比赛

- 房间状态依次为 `LOBBY → LOADING → COUNTDOWN → PLAYING → RESULTS → LOBBY`；暂停状态单独处理。
- 房主只能在名单内所有真人玩家准备后开始比赛。变更比赛设置会使准备状态失效。
- 加载确认来自本轮玩家名单；房主等全部玩家加载完成后才开始倒计时，超时则返回休息室。
- 比赛中不接纳新玩家。已在本局的客户端可按恢复流程重新加入。
- 后院场景和大厅移动由房主模拟；种植、货币、物品栏和外观存档保留在各玩家本机，不通过联机同步。

## 输入计时与公平性

客户端输入带本局编号、递增序号和估计的房主时间。房主检查输入序号和时间窗口，并对自然吹气时间提供有限延迟补偿。吹泡泡仍须实际按住至少 0.3 秒；口哨增加的进度不算作吹气时间。泡泡爆裂、口哨效果和分数由房主裁定。

恢复检查点保留玩家身份、比分、外观、比赛状态和玩法所需的随机状态。异常断线期间的短暂回退可能由最近一次检查点恢复造成。房主接替依赖玩家之间能够相互访问 UDP 7000；只有房主能被其他玩家访问的网络不保证可以完成接替。

## 修改协议

修改 RPC、同步字段、输入语义或状态恢复格式时：

1. 同步更新主机和客户端代码，并检查恢复检查点读写双方。
2. 对不兼容变化递增 `PROTOCOL`；更新 `BUILD` 与 `project.godot` 中的版本标识。
3. 更新本说明及相关网络烟雾检查。
4. 确认房主和客户端使用相同构建。
